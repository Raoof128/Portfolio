# Artwork, project evidence and shared-control inventory

Source-derived inventory for the artwork/UI lane. Source coverage is recorded separately in `frontend-artwork-coverage.json` (53 files). A state listed below means the source implements it; it does **not** mean a browser exercised it. N/A states are intentionally absent rather than invented features.

The scoped lane run completed 183 passing tests across 13 files on 2026-11-03 before the dependency update (Vitest4.1.11). Parent final runs against Vitest4.1.12 take precedence. Unit tests use jsdom/mocked browser boundaries; they do not prove rendered hover contrast, touch affordances, native Clipboard API delivery, or assistive-technology speech. Browser evidence is parent-owned and must be linked separately.

## Noninteractive artwork and structural primitives

- **Original artwork retained:** Royal Abyss / Invisible Window, Fire Shield / Simurgh, Cosmic Loom / Zurvan, Dandelion / GitSwitch, DNA Helix / Mehr Guard, Kinetic Lotus / Syllabus-Sync, Blue Butterfly / Divan, Kinetic Astrolabe / Nexus, Celestial Catcher / NanoMatch, Cosmic Oracle Eye / SentinelFlow, Constellation Owl / ECRSM, Koi Pond / SimurghForge, Wheels of Ezekiel / Aion. These are decoration adjacent to real project text (`aria-hidden`); they are not unnamed controls. Their meaningful states are active animation, paused still, reduced-motion still and offscreen/inactive disposal or pause. Hover/focus/selected/disabled/error/success states do not apply to the drawings themselves. Import loading/retry belongs to ProjectMotion/Thumbnail above.
- **Canvas lifecycle:** shared `createCanvasPlayback` checks application active state, intersection, hidden document and motion preference; bounds DPR in renderers; renders a complete still; redraws after resize/context restore; disposes RAF/listeners/observers. `canvas-playback.test.tsx` tests visibility/reduced-motion/frame pacing, cleanup, context restoration and four real canvas components rendering without a continuing loop. Actual battery use/GPU frame time and visual still-frame quality remain browser/device work.
- **SVG/CSS artwork:** `useArtworkPause` applies `data-art-paused`; each artwork includes reduced-motion styling and scoped `useId` IDs. Its source was read fully, but the scoped unit suite does not test every CSS animation's painted pose. Parent screenshot evidence must distinguish these limits.
- **`Card`, `GlowCard`, `HUDFrame`, `AnimatedSection`, `MotionPreferences`:** structural surfaces/wrappers with children, optional title/classes and native attributes where declared. Card has optional interactive hover styling but no implicit click action. AnimatedSection is deliberately static; MotionPreferences applies user reduced motion to retained Framer Motion descendants. Card tests cover child/classes/native content; other wrappers have full source review without standalone browser-state evidence in this lane.
- **`OSIcon`, `OSMark`, `SignalVortex`:** decorative labelled-neighbour glyphs/brand mark/404 artwork, with no controls or user-facing loading/error states. SignalVortex unit test verifies decorative semantics and21 rings.
- **Copy/context/registry helpers:** `atlas-copy`, `atlas-journey-copy`, `proof-atlas-context`, `project-artwork` supply localised data, visibility and lazy module identity. They have no independent rendered control states; integration tests above cover the consumer behaviours.

## Inventory limits

This lane does not own the taskbar, welcome orb, window captions, search dialog, window drag/resize, ReadingWindowControls, route-level résumé/contact links or language menu. They belong to other source lanes and the parent browser inventory. Their omission here is ownership, not a claim of complete application control coverage. No software-keyboard, physical-device, real assistive-technology or field performance result was produced by this lane.
