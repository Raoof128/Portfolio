## Findings requiring correction

### HARNESS-01 — Snapshot extension validates too late (medium)

`snapshot.mjs` originally wrote route JSON and PNGs at lines93–101, then checked the existing manifest export identity at104–109. Calling `--extend` against a different export would throw after replacing the old phase's page captures. The README's preservation guarantee therefore did not hold on that error path. Move validation before route writes and reject accidental existing-phase replacement. This does not invalidate a run whose export identity actually matched, but the failed path must preserve existing evidence.

### HARNESS-02 — Broad label mask understated excluded title material (medium reporting)

`compare.mjs` originally excluded a fixed400×32px rectangle from the640px window's title strip. The visible Projects text and icon are substantially narrower. Although raw metrics remained available and the mask coordinates were disclosed, describing this as only a label/icon exclusion was imprecise: it excluded otherwise comparable glass. Use measured text-node Range and icon bounds, unioned between candidate/reference with an explicit halo allowance, while preserving the frame edge. Recompute the two window rows; unaffected caption/control crops remain unmasked and need no recapture.

Both corrections have been implemented by the harness author and independently verified below.

## Confirmed properties

- Commands use `execFileSync` with fixed Git arguments. No arbitrary user shell text is executed. Phase names are constrained to lowercase alphanumeric/hyphen. The comparison reads frozen local markup/styles and does not run application scripts. No unexpected upload or external write was found.
- Actual candidate DOM/class/ancestor specificity is retained; isolation deliberately clears unrelated ancestor backgrounds and hides outside pixels. The README explains that this is an isolated visual specimen, not the live webpage. Window/body geometry is explicitly normalised; control natural/live dimensions are recorded before camera changes.
- 7.css source bytes are read without mutation and their SHA256 is recorded. Font faces are made equally available in both specimens; the reference family is explicitly matched through `--w7-font` while its9pt size is retained. Both before/final result sets contain the same nine frozen font hashes and lengths.
- Captions/buttons keep their natural sizes. Fluid input/select/tab widths are explicit comparison constraints. Their previously measured heights are retained rather than silently resized to the reference. Geometry differences remain separately reported.
- Hover and pressed use actual Playwright pointer operations. Focus uses keyboard modality plus focused element verification. A CSS custom-property sentinel checks the pseudo-state; it does not alter appearance. Both available56-case result sets had no failed recorded hover/pressed/focus predicates. Restore/inactive/disabled state mutations are explicitly documented as synthetic styling specimens, separate from React workflow tests.
- The comparator does not resize images. Different extents count as different pixels even when the missing area would match white padding. RGB-only comparison is valid for these opaque screenshots; alpha compositing is expressly out of scope.
- The16/255 maximum-channel band is a descriptive metric, not a pass threshold. A zero above-band count must never be called exact pixel identity. Raw exact counts and mean absolute RGB deltas are also retained; chrome masks do not replace raw metrics.
- PNG filter reconstruction0–4 and encode logic were inspected. The test fixtures are independently encoded rather than generated by the same encoder under test. CRC/input-hardening is limited, acceptable only for trusted browser-generated local artifacts, as currently used.

## Scope limitations

Only Chromium/light-theme isolated pair measurements are produced by this harness. Other themes, complete routes, responsive layouts, keyboard workflows and other browser engines require the separate native suites. The source manifest covers tracked application TS/TSX/CSS; it is not a claim to hash every configuration, documentation file or untracked new script. No universal parity score or WCAG certificate is justified by these measurements.
